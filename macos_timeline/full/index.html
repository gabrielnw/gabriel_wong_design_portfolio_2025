macOS Timeline

macOS Timeline proposes a time-based interface as an alternative to the traditional file system. Documents have long been accessed through place: folders, directories, desktops. Human memory, however, works differently; it recalls context, moments, and experiences. By replacing spatial navigation with a scrubbable timeline, users can revisit any point in their digital history, seeing which files were open, which apps were in use and what music was playing, then resume or branch from that moment.

PROBLEM STATEMENT

Digital files are traditionally organized by place: folders, directories, and storage locations. Yet human memory does not work this way. People remember context, moments, and experiences — not physical or digital locations.

Several Recurring Challenges

  1. Files exist in isolation with no clear links between related content.
  2. Related files are scattered across folders, apps, and formats.
  3. Versioning creates chaos, with multiple copies and inconsistent naming making it hard to track progress.
  4. The creative process disappears — iteration, exploration, and decision-making leave no visible trace, making it difficult to revisit or understand past work.
  5. Together, these issues make revisiting files slow, confusing, and disconnected from how people actually remember their work.

THEORETICAL FOUNDATION

Memory Is Tied to Time and Context

Tulving (1972) separated episodic memory, our memory of personally experienced events, each anchored to a time and a place, from semantic memory of facts. Remembering a piece of work ("the draft I wrote the night before the review") is closer to the first kind, yet folders ask for the second: a category decided at the moment of saving.

Godden and Baddeley (1975) showed that recall improves when the context at retrieval matches the context at learning. That is the basis for the intersection search: cueing the app, the song or the meeting that surrounded a document gives memory more to work with than a filename alone.

How People Actually Keep Files

Malone (1983) found that people keep both tidy files and loose piles, because classifying things is hard, and that piles do useful work as reminders of what still needs attention. A pile is roughly ordered by time, with the latest on top, which is the behaviour Timeline turns into a system.

The research also pulls the other way. Barreau and Nardi (1995) found that people return to files by browsing to where they put them, using location itself as a reminder, and Bergman et al. (2008) found that this preference for navigating over searching held even as search got better. A time-based system has to respect that: the timeline needs to be something you can browse and scrub through, not only a search box.

Earlier Attempts

Organising files by time is not new. Lifestreams (Freeman and Gelernter, 1996) replaced folders with a single time-ordered stream of documents, and Windows 10's Timeline (2018) showed recent activity by date. Both treat time as a list to scroll. This project adds two things on top: documents that keep their own history, and links that form from how files are used together.

Alexander Obenauer's OLLOS, an experimental operating system built around a timeline, is the closest recent work. We presented an early prototype to him during the project, and his main advice was to lean into searching by context.

IDEATION

CONCEPT

1. Documents as Living Entities

Each document is treated as a continuous, living object, containing all versions, edits, and branches in a single place. Rather than creating multiple files for iterations, a document evolves over time, preserving the creative process. Users can view the document's full history, see how ideas developed, revisit past ideas, compare changes without losing context.

2. Contextual Linking

Instead of relying on folders or manual organization, documents form connections based on how they are used together. Each time two or more files are opened or edited in the same context, a link is created and strengthened over time. These relationships allow documents to self-group naturally, reflecting real workflows rather than artificial folder structures. The grouped files exist in dynamic spaces that emerge from activity and shared metadata, making it easy to discover related content, navigate projects intuitively, and see the relationships between files that were previously invisible.

3. Search Through Context

Your memory works by context, not filenames. Intersectional Search lets you find any document by stacking filters: the app you had open, the song you were listening to, or the meeting it was tied to. The more context you add, the more precise your results.

PRIVACY NOTE

A common first reaction is to compare this to Microsoft's Recall, which continuously screenshots user activity and processes it through an on-device AI model. That approach creates a searchable visual record of everything on screen, including passwords, private messages, and sensitive documents, raising serious privacy and security concerns. This project takes a fundamentally different approach. It works with metadata only: which app was in focus, which file was open, what song was playing, and when. No screen content is captured, stored, or analyzed. The result is a lightweight temporal index rather than a surveillance log. Metadata can still be revealing, but it captures far less than a recording of the screen.
